# Three-minute demonstration plan

Record the real application with synthetic PDFs only. Keep the Meta key, Billing screens, personal tabs and private documents out of the recording. Pre-run the live analyses in separate tabs so the video can show completed results without spending its runtime waiting for inference. Clearly identify these as completed live runs; do not simulate tool activity.

| Time | Show | Point to demonstrate |
| --- | --- | --- |
| 0:00-0:20 | App title and two sample statements | One document set, a verifiable reconciliation task. |
| 0:20-1:00 | Contradiction result; click both interest sources | $100 vs $125, $25 discrepancy, highlighted original evidence. |
| 1:00-1:40 | Math-error result; show calculator operands and click stated-total source | Components total $3,300 while the document states $3,350. The calculator finds $50 too high. |

| 2:35-3:00 | Test evidence and repository | Explain supported scope, public code, synthetic ground truth and what was built during the event. |

## Recording acceptance checklist

- Exactly three minutes or within the submission form's confirmed limit.
- Readable amounts, source highlights and calculator values at normal playback size.
- Both $25 and $50 cases shown; review case clearly distinguished from a clean result.
- Audio matches visible behavior and makes no universal-accuracy claims.
- No unrelated existing product functionality presented as hackathon work.
- Export and public repository links accessible.
- Final video URL opens for a viewer without special account access.

This file is a shot plan, not a completed video.
